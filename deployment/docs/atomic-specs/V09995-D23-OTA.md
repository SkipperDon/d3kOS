## 1. Why / Scope

After imaging the lab Pi and deploying to the boat, any subsequent d3kOS update currently requires a physical visit to swap the SD card. D23 eliminates this constraint for T1+ operators by adding a Pi-side OTA agent that polls a HostPapa command queue and self-installs signed release archives on command.

**In scope:**
- `d3kos-ota-agent.py` — new Pi-side polling + install service
- `d3kos-ota-agent.service` — new systemd unit
- `ota-queue.php` — new HostPapa endpoint (command queue + result posting)
- `amboat_ota_commands` MySQL table
- T1+ tier gate (T0 = no OTA, requires physical access)
- Guard tests (pytest)

**Out of scope:**
- Phone app UI that triggers the OTA (mobile app work, separate release)
- Release signing key management (operator generates and holds the key)
- D17 hardware-profile.json gating — OTA logs profile version in result only; it never blocks on hardware

## 3. Pi-Side: d3kos-ota-agent.py

### 3.1 Poll interval

60 seconds. Rationale: OTA is operator-initiated, not time-critical. 60 s balances responsiveness against HostPapa shared-host request budget.

### 3.2 Command schema (JSON payload from HostPapa)

```json
{
  "command_type": "ota_install",
  "payload": {
    "version":      "0.9.9.5",
    "download_url": "https://archive.org/download/d3kos-v0.9.9.5/d3kos-v0.9.9.5.tar.gz",
    "sha256":       "abc123...",
    "release_notes": "Optional one-liner shown in result"
  },
  "command_id": 42,
  "pi_id": "device-token-string"
}
```

`command_type` must equal `"ota_install"` — agent ignores all other types (other types belong to the existing cloud_agent.py).

### 3.3 Install flow

```
1. Fetch pending command from HostPapa (GET ota-queue.php?pi_id=TOKEN&action=peek)
2. T1+ gate check (see §5) — abort + post result "tier_insufficient" if T0
3. POST ota-queue.php  action=ack  command_id=N  (marks command "in_progress")
4. Download archive to /tmp/d3kos-ota-{version}.tar.gz
5. Verify SHA-256 — abort + post result "checksum_fail" if mismatch
6. Backup current deployment:
     cp -r /opt/d3kos /opt/d3kos.ota-rollback
7. Extract archive to staging dir /tmp/d3kos-ota-stage/
8. Stop all d3kos-*.service units (except d3kos-ota-agent itself)
9. rsync --archive --delete /tmp/d3kos-ota-stage/ /opt/d3kos/
10. systemctl daemon-reload
11. Start d3kos-*.service units
12. Health check: curl -sf http://localhost:3000/health (5 attempts, 5 s apart)
13a. Health PASS → post result "success" + hardware profile version + new version string
13b. Health FAIL → rollback:
       systemctl stop d3kos-*.service
       rm -rf /opt/d3kos
       mv /opt/d3kos.ota-rollback /opt/d3kos
       systemctl daemon-reload && systemctl start d3kos-*.service
       post result "rollback_complete" + failure detail
14. Clean up /tmp/d3kos-ota-* and /opt/d3kos.ota-rollback (only on success)
```

### 3.4 Result payload (POST to ota-queue.php action=result)

```json
{
  "command_id": 42,
  "pi_id": "device-token-string",
  "status": "success",
  "version_installed": "0.9.9.5",
  "hardware_profile_version": "1.2",
  "detail": "optional error string on failure"
}
```

## 4. HostPapa-Side

### 4.1 Endpoint

File: `mobile/ota-queue.php`

Actions (GET/POST parameter `action`):
- `peek` — returns oldest pending command for `pi_id`, or `{"status":"none"}`
- `ack` — marks command `in_progress` (prevents double-dispatch)
- `result` — writes result, marks command `done` or `failed`

Requires Ed25519 request signature (same pattern as existing `cloud_agent.py` / `tier_service.py`). Rejects unsigned requests with HTTP 403. Rejects T0 devices at this layer too (belt-and-suspenders with §5).

### 4.2 MySQL table

```sql
CREATE TABLE IF NOT EXISTS amboat_ota_commands (
  id            INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  pi_id         VARCHAR(64)  NOT NULL,
  command_type  VARCHAR(32)  NOT NULL DEFAULT 'ota_install',
  payload       JSON         NOT NULL,
  status        ENUM('pending','in_progress','done','failed') NOT NULL DEFAULT 'pending',
  result        JSON         NULL,
  created_at    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  INDEX idx_pi_status (pi_id, status),
  INDEX idx_created   (created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

## 5. T1+ Gate — Exact Python Check

```python
import json, sys

LICENSE_PATH = '/opt/d3kos/config/license.json'

def _check_tier() -> bool:
    """Return True if tier >= 1, False if T0 or file unreadable."""
    try:
        with open(LICENSE_PATH) as f:
            data = json.load(f)
        return int(data.get('tier', 0)) >= 1
    except Exception:
        return False  # fail closed — no OTA if license unreadable

# In the poll loop:
if not _check_tier():
    _post_result(command_id, 'tier_insufficient',
                 'OTA requires Tier 1 or higher. Visit atmyboat.com to upgrade.')
    continue
```

## 6. Systemd Unit

```ini
# deployment/v0.9.9.5/etc/systemd/system/d3kos-ota-agent.service
[Unit]
Description=d3kOS OTA Update Agent (D23)
After=network-online.target signalk.service d3kos-dashboard.service
Wants=network-online.target

[Service]
Type=simple
User=d3kos
Group=d3kos
WorkingDirectory=/opt/d3kos/services/ota
ExecStart=/usr/bin/python3 /opt/d3kos/services/ota/d3kos-ota-agent.py
Restart=on-failure
RestartSec=30
StandardOutput=journal
StandardError=journal
SyslogIdentifier=d3kos-ota-agent

[Install]
WantedBy=multi-user.target
```

`Restart=on-failure` (not `always`) — avoids BUG-105 restart-loop pattern.
`RestartSec=30` — deliberate; a crashed agent should not hammer HostPapa.

## 7. Guard Tests (pytest)

File: `tests/test_d23_ota_agent.py`

All tests import the agent module directly (no network, no Pi hardware required).

| Function | Asserts |
|----------|---------|
| `test_tier_gate_t0_blocks` | `_check_tier()` returns `False` when license.json has `"tier": 0` |
| `test_tier_gate_t1_passes` | `_check_tier()` returns `True` when license.json has `"tier": 1` |
| `test_tier_gate_missing_file` | `_check_tier()` returns `False` when license.json does not exist (fail closed) |
| `test_checksum_pass` | SHA-256 verify function returns `True` for a file whose hash matches |
| `test_checksum_fail` | SHA-256 verify function returns `False` for a tampered file |
| `test_command_schema_valid` | Parser accepts a correctly-shaped command dict without raising |
| `test_command_schema_wrong_type` | Parser rejects a command where `command_type != "ota_install"` |
| `test_result_payload_shape` | `_build_result_payload()` returns a dict with required keys: `command_id`, `pi_id`, `status`, `version_installed`, `hardware_profile_version` |
| `test_rollback_triggered_on_health_fail` | Mock health check always fails → rollback path is called (assert rollback function invoked) |

Minimum bar: all 9 pass before D23 is marked done.
