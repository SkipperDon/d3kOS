# ATOMIC SPEC — BUG-105 (+ BUG-103, BUG-102) — First-boot stability at Tier 0

**Defect:** The self-healing layer (`issue_detector.py` × `remediation_engine.py`) is an unbounded
positive-feedback loop. At Tier 0 — every fresh install — it issues ~40 `systemctl restart`/sec forever,
kills healthy services via systemd's start-rate limit, wrote a 2.6 GB log to the SD card, and froze the
lab Pi on 2026-09-05. It shipped inside v0.9.9.4.1.
**Severity:** CRITICAL — release gate for **v0.9.9.4.2**.
**Tier:** Tier 1 (Fable) authored this spec. **Every step is Tier 2 (Sonnet) implementable.** Exact
`old`/`new` replacements only — never rewrite a file. Step 0 is operator-only.
**Created:** 2026-09-05 (S148)
**Bug records:** `deployment/docs/V09994_BUG_FIXES.md` BUG-105, BUG-103, BUG-102 — read all three first.
**Fix order is a dependency chain:** BUG-103 (so the next crash is diagnosable) → BUG-105 (the loop) →
BUG-102 (why the loop had fuel). Do not reorder.

**Operator decisions already made (S148) — do not re-open:**
- Tier 0 on first boot is **correct**. The tier service's fail-closed behaviour is not a bug.
- d3kOS **must run cleanly with no cameras**. A disabled feature is a silent no-op, never a failed unit.
- No blind watchdogs (standing rule, BUG-09/BUG-23a). A remediator that retries forever is one.

## 2. STEP 1 — BUG-103: make the journal survive a crash

**New file:** `deployment/v0.9.9.4/etc/systemd/journald.conf.d/50-d3kos-persistent.conf`

```
# d3kOS — BUG-103 (S148 2026-09-05)
# Raspberry Pi OS ships /usr/lib/systemd/journald.conf.d/40-rpi-volatile-storage.conf
# (Storage=volatile) to protect the SD card. That made the 2026-09-05 lab-Pi freeze
# undiagnosable: `journalctl -b -1` was empty. This drop-in (in /etc, so it wins)
# turns persistence on with hard caps so SD wear stays bounded.
[Journal]
Storage=persistent
SystemMaxUse=200M
SystemMaxFileSize=25M
MaxFileSec=1week
Compress=yes
```

**Why not edit `/etc/systemd/journald.conf`:** the RPi drop-in in `/usr/lib` is applied *after* the main
file. Only a drop-in in `/etc/systemd/journald.conf.d/` with a name sorting after `40-` overrides it.
`50-` does. Verify with P9 after deploy: the last `Storage=` printed must be `persistent`.

**Deploy (lab Pi):**
```bash
sudo mkdir -p /etc/systemd/journald.conf.d
sudo cp 50-d3kos-persistent.conf /etc/systemd/journald.conf.d/
sudo chmod 644 /etc/systemd/journald.conf.d/50-d3kos-persistent.conf
sudo systemctl restart systemd-journald
```
`Uncertainty flag: journald restart on systemd 257 is documented to preserve service stdout/stderr
streams, but verify — T14 below asserts a post-restart log line is captured. If T14 fails, services
that log via StandardOutput=journal need a restart; report before doing so.`

Note for the record: `regenerate-identity.sh` (BUG-39) rewrites `/etc/machine-id` ~3 s after boot, *after*
journald has started. journald's directory is keyed to the boot-time id; `journalctl` still reads all
of `/var/log/journal/*`, so this is cosmetic. Do not "fix" it here.

```
    def run_cycle(self):
        """One pass over open issues.
        BUG-105 brakes: at most ONE systemctl action per service per pass, and a row that
        fails MAX_ATTEMPTS times is retired as status='failed' instead of retried forever."""
        decided = {}   # service_name -> success bool, shared by rows naming the same service this pass
        conn = sqlite3.connect(self.db_path)
        cursor = conn.cursor()
        cursor.execute('''
            SELECT id, category, severity, description, metrics
            FROM issues
            WHERE status = 'detected'
            ORDER BY severity DESC, timestamp ASC
        ''')
        issues = cursor.fetchall()

        for issue in issues:
            issue_id = issue[0]
            issue_dict = {
                'id': issue_id,
                'category': issue[1],
                'severity': issue[2],
                'description': issue[3],
                'metrics': issue[4]
            }
            metrics = json.loads(issue_dict['metrics']) if issue_dict['metrics'] else {}
            service = metrics.get('service') if issue_dict['category'] == 'service_down' else None

            if service and service in decided:
                success, action = decided[service], f"Restarted service {service} (same pass)"
            else:
                self.log(f"Attempting remediation for issue #{issue_id}: {issue_dict['description']}")
                success, action = self.remediate_issue(issue_dict)
                if service:
                    decided[service] = success

            if success:
                cursor.execute('''
                    UPDATE issues
                    SET status = 'resolved',
                        resolved_at = ?,
                        remediation_action = ?
                    WHERE id = ?
                ''', (datetime.now().isoformat(), action, issue_id))
                self.log(f"✓ Issue #{issue_id} resolved: {action}")
            else:
                self.attempts[issue_id] = self.attempts.get(issue_id, 0) + 1
                if self.attempts[issue_id] >= MAX_ATTEMPTS:
                    cursor.execute('''
                        UPDATE issues
                        SET status = 'failed',
                            resolved_at = ?,
                            remediation_action = ?
                        WHERE id = ?
                    ''', (datetime.now().isoformat(),
                          f"gave up after {MAX_ATTEMPTS} attempts", issue_id))
                    self.log(f"✗ Issue #{issue_id} retired as failed after {MAX_ATTEMPTS} attempts")
                else:
                    self.log(f"✗ Issue #{issue_id} remediation failed "
                             f"({self.attempts[issue_id]}/{MAX_ATTEMPTS})")
            conn.commit()

        conn.close()
        return len(issues)

    def run_remediation_loop(self):
        """Continuous remediation loop"""
        while True:
            try:
                self.run_cycle()
            except Exception as e:
                self.log(f"Error in remediation loop: {e}")
            time.sleep(CYCLE_SECONDS)

if __name__ == '__main__':
    engine = RemediationEngine()
    if '--once' in sys.argv:          # test harness: one pass, then exit
        engine.run_cycle()
        sys.exit(0)
    engine.run_remediation_loop()
```

## 6. STEP 5 — BUG-102: tier-gated units skip cleanly instead of failing

**Mechanism (Tier 1 decision):** `ExecCondition=` instead of `ExecStartPre=`. When an `ExecCondition`
command exits 1–254, systemd **skips** the unit — final state `inactive`, no `failed`, no `Restart=`
trigger, one info line in the journal. That is the "silent no-op" the operator specified, achieved with
unit-file edits only. `ExecStartPre` exiting non-zero *fails* the unit, which is what fed the storm.

All four units are then re-tried by one timer (6.5) so they come up when the tier changes.
